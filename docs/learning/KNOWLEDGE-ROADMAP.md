# 知识学习路线（L1–L6 学习层级）

> **重要区分**：本页的 L1–L6 是**学习层级**，不是 `docs/MATURITY.md` 的工程成熟度 L0–L6。两者含义不同，不得混用。
>
> 目标：从已具备 Python / FastAPI / RAG / Agent 基础，逐步掌握商业级完整软件交付能力。本轮只提供路线，不启动训练项目。

## 学习层级

| 层级 | 名称 | 目标 | 完成证据 |
|---|---|---|---|
| L1 | 理解完整生命周期 | 能说清 11 阶段与 18 活动的顺序与依赖 | 能画出自己的阶段图并解释每个 Gate |
| L2 | 掌握阶段输入/输出/验收 | 能独立写出每个阶段的输入、产出与验收标准 | 一份真实项目的 Spec + Tickets + 验证计划 |
| L3 | 会选择和调用 Skill | 能按阶段选择主用/替代 Skill，并说明触发与不触发 | 一份 Skill 选择记录与理由 |
| L4 | 受控 Agent 开发 | 能用 Ticket + Harness 约束 Agent 完成单张切片 | 一张 Ticket 的测试、diff、审查记录 |
| L5 | 安全/部署/运维/验收 | 能完成安全负例、发布回执、回滚与用户验收 | 发布回执 + 回滚演练 + 验收记录 |
| L6 | 形成可复用工程能力 | 能从真实失败提炼测试/规则/Skill 候选 | 两个真实项目的复用证据 |

### L1 · 理解完整生命周期

- **前置**：能读写代码、使用 Git、理解 HTTP 与数据库基础。
- **最小理论**：11 阶段、8 宏阶段、18 活动的映射；证据分层（代码/CI/预发/发布/验收）。
- **实践任务**：为你的一个已有小项目画出 11 阶段路线，标出每阶段 Gate。
- **典型错误**：把 18 活动当成 18 个串行阶段；把 8 宏阶段当成第二套生命周期。
- **通过标准**：能解释为什么 11 阶段是唯一权威。

### L2 · 掌握各阶段输入、输出和验收

- **前置**：L1。
- **最小理论**：Spec/AC、ADR、Tracer Ticket、证据模型。
- **实践任务**：为一个真实小需求写 Spec（含负例）、3 张纵向 Ticket、验证计划。
- **典型错误**：AC 不可验证；Ticket 横向切片；验证计划没有命令。
- **通过标准**：每条 AC 有验证方法；每张 Ticket 可独立验证。

### L3 · 会选择和正确调用 Skill

- **前置**：L2。
- **最小理论**：Prompt / Skill / MCP / Plugin / Framework / Harness / Loop 的区别；Skill 状态阶梯。
- **实践任务**：为每个阶段选择一个主用 Skill 与一个替代，说明触发/不触发与验收。
- **典型错误**：把仓库整体当成每个 Skill 都可用；把 `implementation-plan` 当成 `implement`/`tdd`；把安装当验证。
- **通过标准**：能说明来源、许可证、触发条件与验收方式。

### L4 · 使用 Coding Agent 完成受控开发

- **前置**：L3。
- **最小理论**：Harness（上下文、工具、权限、反馈）、有界 Loop、停止条件。
- **实践任务**：用一张 Ticket 跑完 `PREPARE→RED→IMPLEMENT→GREEN→VERIFY→REVIEW→RECORD`。
- **典型错误**：无停止规则；Agent 超范围改动；删除断言换通过；无证据声称完成。
- **通过标准**：测试通过、diff 在范围内、审查记录完整。

### L5 · 安全、部署、运维和客户验收

- **前置**：L4。
- **最小理论**：威胁建模、迁移升降级、备份回滚、可观测性、UAT。
- **实践任务**：完成一次预发验证、发布回执、回滚演练与用户验收。
- **典型错误**：CI 通过冒充生产验收；无备份发布；服务在线当业务验收。
- **通过标准**：发布有平台回执；回滚可执行；消费者验收有记录。

### L6 · 从真实项目形成可复用工程能力

- **前置**：L5 + 至少两个真实项目。
- **最小理论**：知识晋级阶梯（Project Evidence → Domain Pattern → Durable Principle）。
- **实践任务**：从两个真实失败中提炼测试/规则/Skill 候选，并记录复用证据。
- **典型错误**：单次事件宣称 Skill 稳定；把文档数量当能力。
- **通过标准**：两个独立项目的复用证据 + 评审记录。

## 30 + 60 天路线

### 0–30 天：一个真实可运行、可验证的 Web MVP

- **目标**：从需求到部署，完成一个真实 MVP。
- **活动重点**：A01、A04、A05、A06、A07、A10、A11、A12、A16、A17、A18。
- **交付**：至少 3 张纵向 Ticket；测试、部署、备份、用户验收。
- **对应层级**：L1–L4。
- **最小理论**：Spec/AC、认证与数据边界、迁移、E2E、发布回滚。
- **典型错误**：跳过 Spec；只测 happy path；无回滚。

### 31–90 天：企业系统 + Agent 工作流 + 可选小程序

- **目标**：掌握权限、集成、UAT 与 AI Overlay。
- **活动重点**：A02、A03、A08、A09、A13、A14、A15、A16、A17。
- **交付**：一个企业场景 + 一个 Agent 工作流；小程序/APP 为可选分支。
- **对应层级**：L4–L6。
- **最小理论**：RBAC/SSO、集成幂等、Agent Tool/State/HITL、安全负例。
- **典型错误**：前端隐藏代替服务端授权；AI 绕过平台权限；无评测上线。

## 已有基础如何复用

- 已有 Python / FastAPI：可直接进入 A06/A07/A10，不必重学语言。
- 已有 RAG：可直接进入 A03/A11 的评测部分，但必须补检索评测集。
- 已有 LangGraph / Agent：可直接进入 A09/A15 的 Tool/State/HITL 与安全边界。
- 缺少的部分通常是：Spec/AC、UI/UX、数据库迁移、E2E、发布回滚、用户验收。

## 边界

- 本路线不启动训练项目；不安装 Skill；不产生真实项目证据。
- 完成学习层级不等于工程成熟度晋级；`docs/MATURITY.md` 的 L0–L6 仍由 `xeng maturity` 基于真实检查输出。
- 真实项目 Dogfood 仍为 `NOT_RUN / BLOCKED`。
