# 四类产品开发指南与横切说明

> 所有路线复用同一套 11 权威阶段与 18 活动；本文只增加路线特有的前置条件、平台限制、负例与 Gate，不建立新的状态机。

## 路线总览

| 路线 | 权威阶段重点 | 平台不可替代环节 | 关键负例 |
|---|---|---|---|
| SaaS / Micro-SaaS | discovery→spec→architecture→implementation→verification→release→operation | 支付渠道回执、生产租户验收 | 跨租户读写、会话失效、重复回调 |
| 企业 Web / 管理系统 | discovery→spec→architecture→planning→implementation→verification→release | 企业 IdP 联调、业务方 UAT | 越权审批、审计日志删除、集成重复回调 |
| 微信小程序 | spec→architecture→implementation→verification→release | 微信平台审核、真机 | 无会话、非法域名、越权读取 |
| 移动 APP | spec→architecture→implementation→verification→release→operation | 商店审核、签名、真实设备 | 断网丢状态、权限拒绝崩溃、单平台证据冒充 |

---

## SaaS / Micro-SaaS

**完整流程**

1. **需求与价值**（A01/A02）：确认租户模型（单租户 / 组织多租户 / 工作区）、认证方式、计费边界。
2. **Spec/AC**（A04）：每条 AC 必须包含租户边界与权限负例。
3. **架构**（A06/A07）：数据层强制租户隔离；迁移含升级与降级；会话与令牌生命周期。
4. **Tickets**（A08）：首张切片通常是“登录 + 读取本租户数据”。
5. **实现**（A10）：服务端授权，不靠前端隐藏。
6. **验证**（A11/A12/A15）：跨租户隔离探针、认证绕过负例、支付回调幂等。
7. **发布**（A16）：备份、迁移升降级、部署回执、回滚。
8. **运营**（A17）：指标、告警、成本、事件台账。

**必备 Gate**

- 租户 A 无法读取/修改/枚举租户 B 数据。
- 匿名与过期会话被拒绝。
- 迁移升降级在副本上验证。
- 支付启用时：回调验签、金额服务端校验、重复回调幂等、对账。

**平台限制**：真实支付需要商户资质与沙箱/生产凭据；本地代码测试不能替代渠道回执。生产租户数据验收必须由业务方在授权环境完成。

**常见失败**：把租户过滤放在前端；迁移无回滚；把支付开关当已完成。

## 企业 Web / 管理系统

**完整流程**

1. **需求访谈**（A01/A02）：角色、流程、审批、例外、数据归属、停机窗口。
2. **Spec/AC**（A04）：业务流程图 + 权限矩阵 + 字段级授权。
3. **架构**（A06/A07）：SSO（OIDC/SAML）、RBAC、审计日志保留、集成契约。
4. **Tickets**（A08）：首切片通常是“角色受控进入 + 读取最小数据”。
5. **实现**（A10）：最小权限与职责分离；外部集成幂等与重试。
6. **验证**（A11/A12/A15）：RBAC 越权负例、集成超时/重复回调、审计不可静默删除。
7. **发布与交接**（A16/A18）：迁移、回滚、UAT 签收、运行交接手册。
8. **运营**（A17）：审计日志、告警、恢复演练。

**必备 Gate**

- 无权限角色、过期会话、越权审批被拒绝。
- 企业集成契约测试通过，超时与重试幂等。
- 业务方完成 UAT 签收；运行交接人确认。

**平台限制**：SSO 联调依赖企业 IdP 与管理员授权；ERP/CRM 需要接口文档、测试账号与网络准入；UAT 与生产切换必须由业务方在授权窗口完成。

**常见失败**：用前端菜单隐藏代替服务端授权；审计日志可被静默删除；集成无幂等导致重复写入。

## 微信小程序

**完整流程**

1. **平台与主体**（A01）：AppID、主体资质、类目、服务范围、备案适用性。
2. **Spec/AC**（A04）：登录态、合法域名、隐私授权、空态/错误态。
3. **架构**（A06/A07）：微信官方登录 + 服务端会话；合法请求域名；分包策略。
4. **实现**（A10）：原生 / Taro / uni-app / 微信云开发，四选一。
5. **验证**（A11/A12/A15）：真机主路径、弱网、冷启动、非法域名、越权读取。
6. **发布**（A16）：体验版、提审、平台审核、发布回执。
7. **运营**（A17）：版本迭代与回滚。

**必备 Gate**

- 真机完成登录与业务主路径，保留设备与基础库版本。
- 弱网、冷启动、空态降级可复现。
- 体验版配置与平台审核回执可查；未获回执保持 `NOT_RUN`。

**平台限制**：平台账号资质、类目审核、合法域名、提审属于平台控制；本地代码测试不能替代平台回执。AppSecret 不得写入客户端或仓库。

**常见失败**：把开发者工具当真实设备；把“提交审核”当“已发布”；客户端包内出现密钥。

## 移动 APP

**完整流程**

1. **技术栈选择**（A01/A06）：Flutter / React Native / 原生 Android / 原生 iOS，**择一**。
2. **Spec/AC**（A04）：目标设备与系统版本矩阵、权限、离线、安全存储。
3. **架构**（A06/A07）：路由、状态、原生能力边界、API 集成。
4. **实现**（A10）：所选技术栈；不同时引入四套端。
5. **验证**（A11/A12/A15）：模拟器/真机黄金路径、断网重连、权限拒绝。
6. **发布**（A16）：签名构建、TestFlight/测试轨道、商店审核、灰度、回滚。
7. **运营**（A17）：崩溃监控、版本回滚、OTA 策略。

**必备 Gate**

- 目标设备/模拟器安装并完成黄金路径，保留构建版本。
- 断网重连与权限拒绝负例通过。
- 签名构建与测试分发回执可查；商店审核未完成时保持 `NOT_RUN`。

**平台限制**：签名证书、商店主体、隐私声明、审核属于平台控制；推送/支付/地图 SDK 需要各自账号与资质。

**常见失败**：用单一平台证据冒充另一个平台；未签名就声称发布；离线冲突导致重复提交。

## 纯静态 Web 工具 vs SaaS

| 维度 | 纯静态 Web 工具 | SaaS |
|---|---|---|
| 数据 | 浏览器本地 / 无后端 | 数据库、租户、备份 |
| 身份 | 通常无账号 | 认证、会话、权限 |
| 计费 | 通常无 | 订阅、支付、对账 |
| 部署 | 静态托管即可 | 应用 + 数据库 + 迁移 |
| 主要风险 | XSS、依赖、可访问性 | 租户隔离、迁移、支付、可用性 |
| 可裁剪阶段 | 可裁剪 A07 认证与迁移 | 不可裁剪租户与迁移 |

静态工具可以走更短的路线（intake→specification→implementation→verification→release），但**不能因此跳过安全负例**（XSS、依赖审计、可访问性）。

## Greenfield / Brownfield 入口

### Greenfield（`mode: new`）

- 从任务定义的第一个阶段开始。
- 允许最小 Spec，但必须包含非目标与权限负例。
- 首张 Ticket 纵向穿过 UI→API→DB→测试。
- 风险：过早选型、过度设计。控制：先最小可运行骨架，再迭代。

### Brownfield（`mode: existing`）

- 自动在最前面补 `intake` + `discovery`。
- 先读项目本地 `AGENTS.md` / `CLAUDE.md` 与真实 CI。
- 文档与代码冲突须记录，不得静默采纳。
- 先补回归测试，再改行为。
- 风险：破坏现有契约、无回归网。控制：小步替换、兼容窗口、迁移升降级。

## AI Overlay

AI 能力（LLM / RAG / Agent / 多 Agent / 自动化工作流 / AI-native UX）是**叠加层**，不是绕过底层平台的捷径。

- AI Overlay **不能绕过** Web/SaaS/企业平台的权限 Gate。
- AI 能力需要 `eval`、`integration-probe`、`review` 证据。
- 模型输出视为不可信输入；提示词不得含密钥。
- 必须有降级与人工接管路径。
- 脚本假模型、静态扫描、CI 通过不能替代真实模型评测或用户验收。
- RAG 需要检索评测集（Hit@K / Recall@K / MRR）与金标文档；Agent 需要 Tool/State/Authorization/HITL 契约。

## 专用工具而非 Skill 的环节

以下环节应由专用工程工具或平台控制完成，**不应强行寻找 Skill**：

| 环节 | 应使用的工具/控制 |
|---|---|
| 数据库迁移 | 迁移工具（如 Prisma/Drizzle/Flyway）+ 升降级脚本 |
| 支付对账 | 支付渠道沙箱/生产回执 + 对账脚本 |
| 企业 SSO | 企业 IdP 配置 + 管理员授权 |
| 微信审核/发布 | 微信公众平台 |
| APP 签名/商店审核 | 签名工具 + App Store Connect / Google Play Console |
| 密钥/依赖扫描 | 专用扫描器 + CI |
| 浏览器 E2E | Playwright 等测试工具 |
| 监控告警 | OpenTelemetry / Sentry / 平台告警 |

Skill 负责“过程知识”，工具负责“确定性执行”。两者不能互相替代。
