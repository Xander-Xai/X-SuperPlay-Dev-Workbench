# Workbench v0.4 需求：文档真实性、流程/Skill 现代化与协作装配

> 状态：`APPROVED_FOR_IMPLEMENTATION`。  
> 依据：`docs/research/2026-11-01-skill-and-flow-audit.md`。  
> 本文件定义“做什么”和“怎样算完成”；实现细节在代码与 PR 中，不在本文件重复。

## 1. 目标

在不引入运行时依赖、不复制第三方 Skill 正文、不新增第二套生命周期的前提下：

1. 让 README、ROADMAP、AGENTS、版本号与真实仓库状态一致；
2. 修掉会导致浏览器崩溃、CLI 输出错误、Skill 安装不全的 P0 缺陷；
3. 把 8 个候选 Skill 扩展到 14 个，并让每个阶段都有当前主流的主用 Skill；
4. 把四条路线与 AI Overlay 的 2026 平台/合规 Gate 写进 catalog 与测试；
5. 把 plan mode、subagent、worktree、写者/审者、人工 Gate 装配成可校验的协作模型；
6. 重建六视图站点并提 PR，合并后由 Pages 部署。

## 2. 范围与不在范围

范围：`src/`、`tools/`、`test/`、`skills/`、`docs/`、`README.md`、`AGENTS.md`、`CONTRIBUTING.md`、CI 与站点文案。

不在范围：

- 新增第三方运行时依赖；
- Vendor 任何第三方 Skill 正文；
- 自动创建 worktree、自动合并、自动发布、自动平台提审；
- 新增站点视图、第二套生命周期或 i18n/深链接；
- 真实项目 Dogfood、Skill 晋级证据记录器、Loop Runner、eval 执行器。

## 3. 编号需求

每条需求包含验收标准（AC）和验证方式（Verify）。

### R1 文档真实性

**需求**：README、ROADMAP、AGENTS、`CONTRACT_ALIGNMENT.md`、`SKILL_KIT.md`、学习文档不再包含已证伪的仓库状态、PR 归属、版本号与许可证结论。

**AC**：

- README 状态表反映当前分支基线与真实测试数；PR #31 标为已合并且交付整合归属 PR #30。
- `PROVENANCE` 只作历史溯源，catalog 权威在本仓。
- 版本号统一为 0.4.0。
- 学习文档的 Anthropic 许可证结论与 `EXTERNAL_SKILLS` 一致。

**Verify**：人工逐条对照 `docs/research/2026-11-01-skill-and-flow-audit.md` 的文档声明审计；`npm run check`；相对链接检查。

### R2 浏览器阶段越界崩溃

**需求**：从长路线切到短任务时，阶段列表不得读取越界索引。

**AC**：

- `renderStages` 在读取前 clamp 索引。
- `#project-task` 与 `#project-mode` 变更时重置 `activeStage=0`。
- `clampStageIndex(count, index)` 有 0、负数、越界与 4 阶段路线测试。

**Verify**：`node --test --test-name-pattern="clamp" test/engine.test.mjs`；浏览器复现长路线第 11 阶段 → `bug`。

### R3 `xeng task` 输出与帮助

**需求**：`xeng task <task-id>` 的用法文案正确，`--json` 真正输出 JSON。

**AC**：

- usage 写的是 task id，不是 type。
- `--json` 输出可被 `JSON.parse`。
- 测试覆盖默认与 `--json` 两种输出。

**Verify**：`node tools/xeng.mjs task feature --json`；`test/xeng.test.mjs`。

### R4 `xeng assemble` 与库行为一致

**需求**：CLI assemble 安装的 Skill 集合与 `assemble()` 一致，包含 required + recommended。

**AC**：

- 复用 `stageSkillIds()`，不再只取 required。
- 测试断言推荐 Skill（如 `systematic-debugging`）出现在输出中。

**Verify**：`node tools/xeng.mjs assemble --profile saas,web,backend --task bug`；`test/assemble.test.mjs`。

### R5 Skill frontmatter 开放标准

**需求**：14 个 `SKILL.md` 顶层只保留 `name`、`description`、`license`；扩展字段进入 `metadata` 字符串映射。

**AC**：

- `name` 与目录名一致，`description` ≤1024 且包含触发语义。
- `tools/xeng.mjs validate-registry` 与 `tools/skill-kit.mjs` 从 `metadata` 读取。
- `catalog.mjs` 仍是唯一真值源。

**Verify**：`node tools/xeng.mjs validate-registry`；`test/install.test.mjs`。

### R6 新增 6 个 Skill

**需求**：新增 `implementation`、`security-review`、`release-engineering`、`incident-response`、`eval-engineering`、`agent-collaboration`。

**AC**：

- 每个 Skill 有可执行步骤、失败模式、停止条件、证据要求。
- 每个 Skill 在 catalog 中有 stages、dependencies、tests、installMethod。
- 不复制第三方正文。

**Verify**：`node tools/xeng.mjs validate-registry`；`test/engine.test.mjs` 断言 14 个 Skill。

### R7 重写 8 个旧 Skill

**需求**：现有 8 个 Skill 的正文达到 2026 主流流程深度，保留 ID。

**AC**：

- `project-discovery` 含最小上下文与 interrogate。
- `specification` 含 EARS、场景分类、数据契约、AC→测试。
- `architecture` 含 ADR/MADR、API 契约、fitness function。
- `implementation-plan` 含 HITL/AFK、`blocked_by`、prefactoring、尺寸上限。
- `verification` 含测试金字塔、真实浏览器/真机、性能、flake。
- `code-review` 含风险分级、测试弱化、依赖、可观测性、审者独立。
- `systematic-debugging` 明确不是实现/运营主用。
- `documentation-sync` 收窄为文档漂移同步。

**Verify**：人工审阅 `skills/*/SKILL.md`；`npm run check`；Skill 长度与触发词检查。

### R8 catalog 阶段映射

**需求**：每个阶段至少 1 个 required Skill；release/operation/postmortem 的主用 Skill 正确。

**AC**：

- `implementation → implementation`
- `release → release-engineering`
- `operation → incident-response`
- `postmortem → incident-response`（`documentation-sync` 备选）
- 计数断言从 8 改为 14。

**Verify**：`test/delivery.test.mjs`；`test/engine.test.mjs`；`npm run check`。

### R9 delivery 活动映射

**需求**：18 项活动的主用 Skill 覆盖其阶段，或显式声明 `coverageException`。

**AC**：

- A10/A11 → `implementation`。
- A15 → `security-review`。
- A16 → `release-engineering`。
- A17/A18 → `incident-response`。
- 其余部分覆盖有 `coverageException` 与理由。

**Verify**：`test/delivery.test.mjs`；`node tools/xeng.mjs delivery --json`。

### R10 路线 SOP 2026 Gate

**需求**：SaaS、企业、小程序、APP 的 `ROUTE_SOPS` 含审计列出的 2026 Gate。

**AC**：

- 小程序含 ICP 备案/主体一致、隐私指引 1:1、`requirePrivacyAuthorize`、内容安全 API。
- APP 含 API 36、Xcode 26/iOS 26 SDK、隐私清单、Data Safety。
- SaaS 含 OIDC/SCIM/DPA/审计/DSAR。
- 企业含 OIDC/SAML/SCIM/职责分离/审计 WORM。

**Verify**：`test/engine.test.mjs` 的路线 token 断言；`docs/ROUTE_COMPLIANCE.md` 对照。

### R11 AI Overlay 合规

## 4. 边界

**Always**

- 先写失败测试再修 P0 逻辑。
- 运行 `npm run verify` 后再声明完成。
- 未知保持 `UNKNOWN`，未执行保持 `NOT_RUN`。
- 生成产物保持 `DRAFT_NOT_EXECUTED`。

**Ask first**

- 新增运行时依赖、修改 CI 权限、改变发布/部署流程。
- 删除或重命名既有 Skill ID。
- 引入第三方 Skill 正文或代码。

**Never**

- 提交密钥、`.env`、生产数据。
- 自动合并、自动发布、自动平台提审。
- 绕过 hooks、必需检查或人工 Gate。
- 把 CI 通过当作真实设备/消费者验收。

## 5. 验收顺序

1. Phase 0：审计与需求文档（本文件）。
2. Phase 1：文档真实性。
3. Phase 2：P0 逻辑与 CI。
4. Phase 3：14 个 Skills 与 frontmatter。
5. Phase 4：路线与 AI Gate。
6. Phase 5：协作模型与产物。
7. Phase 6：六阶段对照与 `intent.md`。
8. Phase 7：版本、验证、截图、PR。

每一阶段结束运行相关测试；Phase 7 运行完整 `npm run verify` 与 `npm run build`。
